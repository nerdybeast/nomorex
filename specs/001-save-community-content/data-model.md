# Data Model: Save and Start Community Workouts and Programs

No new tables. One additive migration adds copy-attribution columns to `workouts` and
`programs`, a constraint, a trigger, and two RPCs, and replaces `start_program`.

## `workouts` — new columns

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `is_copy` | boolean | no | `false` | True for a saved copy and anything derived from one (FR-008a). Never reverts to false. |
| `copied_from_user_id` | uuid | yes | — | FK `auth.users(id)` `on delete set null`. Original author. Deliberately not `profiles(id)`: a second FK to `profiles` makes PostgREST reject the existing `profiles(display_name)` embeds as ambiguous (PGRST201). |
| `copied_from_display_name` | text | yes | — | Author's `display_name` snapshotted at copy time (may itself be null → "Anonymous lifter"). |
| `copied_from_workout_id` | uuid | yes | — | FK `workouts(id)` `on delete set null`. The public workout this was copied from (null for workouts generated from a copied program). |
| `copied_from_program_id` | uuid | yes | — | FK `programs(id)` `on delete set null`. The public program a copied program came from — set only on workouts generated by starting a copied program, so their label can name the author while the original exists. |

Indexes: `(user_id, copied_from_workout_id) where copied_from_workout_id is not null` (FR-013 lookup),
plus plain indexes on `copied_from_user_id` and `copied_from_program_id` so `db lint` doesn't flag
unindexed foreign keys.

## `programs` — new columns

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| `is_copy` | boolean | no | `false` | As above. |
| `copied_from_user_id` | uuid | yes | — | FK `auth.users(id)` `on delete set null` (see above). |
| `copied_from_display_name` | text | yes | — | Snapshot. |
| `copied_from_program_id` | uuid | yes | — | FK `programs(id)` `on delete set null`. |

Index: `(user_id, copied_from_program_id) where copied_from_program_id is not null`.

## Workouts generated from a copied program

`start_program` stamps every materialized `workouts` row with the program's `is_copy`,
`copied_from_user_id`, `copied_from_display_name` and `copied_from_program_id` (and leaves
`copied_from_workout_id` null — the source is a program, not a workout). For a non-copied program all four stay at defaults, so
existing behavior is unchanged.

## Validation rules

| Rule | Where enforced | Requirement |
|---|---|---|
| `NOT (is_copy AND is_public)` | `CHECK` on `workouts` and `programs` | FR-008 |
| `is_copy` cannot change `true → false` | `BEFORE UPDATE` trigger on both tables | FR-008 |
| Source must be public, readable, not owned by caller, not archived (program) | RPC pre-checks | FR-018, FR-019 |
| Copy is private | RPC inserts `is_public = false` | FR-008 |
| No logged results copied | RPC copies only template columns of `workout_sets` | FR-006 |
| Exercises resolve in the viewer's catalog | RPC name-mapping (research R4) | FR-007 |

Existing rules still apply to every inserted row: denormalized `user_id = auth.uid()`
(Constitution I), RLS ownership policies, `program_days.position` / `program_weeks.week_number`
unique constraints (copied as-is from a valid source, so no collisions).

## What is copied

**Workout** → new `workouts` row (`title`, `notes`, `date = p_today` — the caller's local date,
not the server's `current_date`, matching every other workout-creation path,
`status = 'not_started'`, fresh `workout_group_id`, `is_public = false`, attribution columns)
→ each `workout_exercises` (`exercise_id` mapped, `position`, `notes`)
→ each `workout_sets` (`position`, `target_reps`, `weight_mode`, `percentage`,
`absolute_weight_kg`, `basis_exercise_id` mapped, `note`).
**Not copied**: `completed`, `actual_*`, session timing, `session_notes`, `program_instance_id`,
`program_day_id`.

**Program** → new `programs` row (`name`, `description`, `is_public = false`,
`is_archived = false`, attribution columns) → each `program_weeks` (`week_number`, `label`,
`notes`, `position`) → each `program_days` (`day_number`, `title`, `is_rest_day`, `notes`,
`position` — global order preserved) → each `program_exercises` (`exercise_id` mapped,
`position`, `notes`) → each `program_sets` (as for workout sets). **Not copied**:
`program_instances`, `is_archived`/`archived_at`.

(Exact column lists to be confirmed against the live schema during implementation; any
template column present on the source must be carried.)

## Client models

`Workout` gains `isCopy` (bool, default false), `copiedFromUserId`, `copiedFromDisplayName`,
`copiedFromWorkoutId` and `copiedFromProgramId`; `Program` gains `isCopy`, `copiedFromUserId`,
`copiedFromDisplayName` and `copiedFromProgramId` (all `String?`), parsed in `fromJson` like
existing fields. A workout's *source id* for labelling is `copiedFromWorkoutId ?? copiedFromProgramId`.

Shared helper (pure, unit-tested): `copyAttributionLabel({isCopy, copiedFromUserId,
copiedFromDisplayName, copiedFromSourceId}) → String?` — null when not a copy; otherwise
`"Copied from <ownerDisplayName(name)>"`, or `"Copied from another user"` when the author or
source id is null.

## State transitions

```text
public source ──copy_workout(start=false)──▶ copy [not_started]
public source ──copy_workout(start=true)───▶ copy [in_progress]   (single transaction)
public program ─copy_program(date=null)────▶ program copy
public program ─copy_program(date=D)───────▶ program copy + program_instance(active, started D)
                                             + one workout per day (all is_copy = true)
```

Copy rows then follow the existing workout session and program-instance lifecycles unchanged.
